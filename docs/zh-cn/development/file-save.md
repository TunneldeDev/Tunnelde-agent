# 原生文件保存（实验中，尚待验收）

0.28.0 包含实验性 `files.save.v1` 实现，仍在审查且未加入能力发现。桌面源码已有
协议和只读恢复适配器，但新编辑器保存及安装／初始化入口仍未启用，尚待完成授权和
验收。它不是稳定插件 API，不能结算旧 SFTP 未知请求；独立准入账本仍然只记录准入。

## 授权与身份

显式选择 helper 后调用 `files-save --directory <绝对状态目录>`，在十秒内通过
标准输入发送一个有界 UTF-8 JSON 请求并关闭输入。令牌只通过标准输入传递，原生
worker 初始化也一样，不放入参数或环境变量。不自行安装或调用 JavaScript 运行时。

`initialize` 要求 `schemaVersion: 1`、`storage: "local"`，以及包含 `hostKey`
（无填充的 SSH SHA256 指纹）、`account`、绝对 `scope` 的 `context`。
适配器必须从已认证连接提供身份；调用者字符串不是 helper 对 SSH 的独立证明。
初始化创建用户显式选定且不存在的私有目录，或检查已有目录，不重置数据库。
Windows 要求固定本地存储上的受保护当前用户 ACL；Unix 要求当前用户所有，且组和
其他用户没有权限。权威绑定代次、规范作用域和实际作用域／状态目录身份；复制
数据库不构成迁移。

## 请求

`submit` 包含 `control`、`intent` 和 UTF-8 `content`。控制信息包含
`schemaVersion`、`authorityId`、`operationId`、`generation`、`intentSha256`
及随机 256 位小写十六进制私有 `token`，仅保存带领域分隔的令牌摘要。
改变身份会被拒绝；准确重复不会再次发布已执行或已结算的任务。

意图包含 `schemaVersion`、`bindingSha256`、相对 `target` 分段、`baseline`
（`kind: absent`，或包含 `sha256`／`length` 的 `kind: existing`）、
`payloadSha256`、`payloadLength`。文本上限 2 MiB。摘要采用递归按对象键排序、
保留数组顺序、无额外空白且使用 serde 兼容字符串转义的 UTF-8 JSON；结构仅包含
字符串、有界整数、对象和数组。领域前缀为 `tunnelde.files.save.binding.v1\0`、
`tunnelde.files.save.intent.v1\0`、`tunnelde.files.save.token.v1\0`，末字节是
NUL；正文使用原始 SHA256。

`status`、`cancel`、`release` 使用原控制身份。释放还要求准确的回执 `revision`、
排除原执行器，且有备份时提供 `discardBackup: true`。

## 执行与恢复

短 SQLite 事务先持久化意图／正文，再启动脱离客户端运行的 worker。操作级内核
租约持续覆盖实际 IO，只有 `prepared` 可开始执行。worker 记录独占私有暂存文件
归属，检查基线、正文和可用的元数据保留能力，在目标变动前持久化进入
`publishing`。此前取消可以获胜，此后不能声称停止发布。worker 最长存活五分钟，
超时退出不编造结果。
Windows worker 除脱离控制台外，还请求作业策略允许的脱离，避免 OpenSSH 请求结束时
一并终止已准入工作。策略拒绝脱离时明确返回启动错误并保留可查询记录，不回退为受会话
约束的 worker，也不隐式重试。
操作系统的会话／作业策略仍可能终止 worker；此时根据原租约和日志恢复状态，
不承诺所有系统策略下都能持续运行。

新建采用原生原子禁止覆盖发布；替换通过 Linux/macOS 交换或 Windows 备份替换
保留实际被置换对象，不使用先截断、先删除或复制后删除的降级路径。发布前冲突
不会改变目标；被置换基线不同会成为**已发布的冲突**，保留并发版本，不盲目回滚。
交换不等于针对任意外部写入者的文件系统比较交换；元数据／安全属性只是某时刻的
观察。保留目录权威不构成同账户恶意原生进程的沙箱，也不能永久阻止其他进程在
路径解析后移动目录。

Windows 替换可能重新继承暂存目录 ACL；记录成功前，执行器通过已核对身份的发布
句柄，从实际被置换的备份恢复并校验所有者、组和 DACL。元数据恢复中断保留备份并
成为未知；元数据恢复和路径发布不是同一个原子操作。新文件默认采用私有访问权限。

最终回执可跨客户端／SSH 回复丢失保留。查询不启动、重放或清理任务，并核对原租约
身份；`live: null` 表示无法证明原执行器已经退出。排除执行器后，发布前中断可记为
失败；发布中断或原生结果不明确必须成为 `unknown`。内容相等或路径缺失不能证明
成功；未知操作阻止该权威接纳新操作。这是进程丢失语义，不承诺所有设备的断电、
网络存储、跨挂载移动或旧 SFTP 请求恢复保证。

`backupRetained: null` 表示未知发布／清理期间无法证明备份仍然可用。准确重复释放
使用原始版本号和丢弃决定，返回已结算回执，不再次删除文件。

显式释放只删除已验证归属的文件，不删除用户目标或递归清理目录。先记录释放意图，
清理中断成为未知；未知保存不能释放。`cleanupAuthorized: false` 始终禁止宿主进行
通用清理，helper 内严格校验的释放是独立行为。

上限为 1024 条记录、四个活动操作、8 MiB 保留正文、32 MiB 数据库，不通过驱逐回执、
取消占位或未知记录接纳新任务。已知终态正文可回收，操作身份仍保留。损坏、不兼容
或不安全的存储会被保留并拒绝。

扩展元数据另设上限：256 项属性、单项 64 KiB、总计 1 MiB。超大的 macOS 资源叉
和与旧正文绑定的压缩元数据会在发布前拒绝，不进行无限复制。

macOS 暂存文件在写入前记录的 device/inode/创建时间身份会贯穿整个操作，包括元数据
复制中断。替换时显式复制所有者／组、模式、ACL、有界扩展属性，以及 `nodump`、
`hidden`、`tracked` 标志，不再使用 `COPYFILE_STAT` 恢复源时间戳。其他文件标志在
发布前拒绝，因为它们可能编码旧正文、需要特权或阻止发布和按原修订清理。现有恢复
身份不会被重写；身份发生变化的残留仍不能清理。

公布能力前仍需文件系统／元数据验收、历史客户端组合、物理 macOS/Linux、桌面授权
与恢复，以及安装包交付。
